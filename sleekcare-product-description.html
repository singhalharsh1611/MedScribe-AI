Production Architecture

An end-to-end intelligent medical transcription and prescription generation system tailored for the Indian healthcare market. It captures ambient clinical dialogue via bespoke dual-facing acoustic hardware, processes speech through real-time Indian-accent optimized ASR, extracts medical entities using specialized medical LLMs, and maps colloquial pharmaceutical data against a custom comprehensive drugs database using in-memory phonetic heuristics.

03 HW: Mic Pod V3

The entire data pipeline begins in the physical world with the Dual-Facing Mic Pod v3. Rather than relying on generic mobile phone microphones, the system uses custom acoustic hardware engineered specifically for the clinical environment.

Hardware Highlights

The capsule features two INMP441 I²S MEMS microphones placed back-to-back, establishing a 1.8m usable pickup radius per end. It boasts 75 hours of battery life from a 250 mAh LiPo cell and caches audio locally onto a 16GB MicroSD card. A central tactile button allows for immediate, hardware-level muting to ensure patient privacy.

04 Step 1: Capture & Encoding

During the patient consultation, the physician speaks naturally. The Mic Pod's on-board Seeed XIAO nRF52840 microcontroller captures the dialogue. Once offloaded to the Node.js backend, the system utilizes fluent-ffmpeg to transcode the audio payload strictly into a raw PCM format (s16le, 1 channel, 16000 Hz) to meet the strict requirements of downstream acoustic models.

05 Step 2: ASR Transcription

The normalized audio stream is routed to our highly scalable Serverless ASR infrastructure, hosted on Modal. Specifically, the system utilizes a custom Whisper-based acoustic model named Parrotlet.

The Express backend establishes a streaming connection using Server-Sent Events (SSE) to push transcription progress instantly back to the clinician's dashboard. Parrotlet accurately transcribes complex pharmacological terminology even in noisy consult environments, returning the final unified text string for downstream processing.

06 Step 3: LLM Extraction

The raw transcript contains noisy clinical conversation. The system passes this transcript to MedGemma (medgemma-4b-it) via the dr7.ai API. Unlike generic LLMs, MedGemma is prompted strictly as an NER (Named Entity Recognition) engine.

Entity Targeting

The MedGemma model isolates exact spoken parameters without hallucinating database corrections: spoken_name, strength, dose, route, frequency, duration, and instructions. It parses compact doctor shorthand (e.g., "rhefdod" is split into medicine "rhefd" and frequency "OD") and outputs a preliminary JSON array.

07 Step 4: Database Mapping

To ensure clinical safety and prevent spelling errors, the extracted drugs are mapped against a massive, localized PostgreSQL database (scraped from platforms like 1mg). To achieve zero-latency matching without an expensive Vector DB, the system loads the entire drug library into an O(1) Memory RAM Cache at startup.

  • Hybrid Matching: The engine utilizes the double-metaphone algorithm to bucket drugs by phonetic sound, combined with a fastest-levenshtein (Sørensen-Dice style) string distance calculation.
  • Clinical Heuristics: The scoring engine heavily penalizes matches that have conflicting dosage forms (e.g., Syrup vs Tablet) or mismatched product qualifiers (e.g., GP1 vs GP2, SR vs XR).
  • Output: Each extracted drug is appended with a top_phonetic and top_fuzzy list of the safest, exact-match pharmaceutical brand names.

08 Step 5: Output Generation

In the final phase, the Node.js backend issues a second call to MedGemma. The LLM acts as a Clinical Pharmacist, reviewing the original transcript alongside the mathematically ranked phonetic/fuzzy candidates.

MedGemma selects the most accurate database brand name, aggregates patient vitals/history, and outputs a highly structured clinical JSON payload. This payload is injected into an HTML prescription_template.html and sent back to the Next.js frontend, presenting the doctor with a flawless, print-ready digital prescription.
